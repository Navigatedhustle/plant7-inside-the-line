# Plant 7 guided demo

Open the existing private tailnet URL, or `http://127.0.0.1:8097/` on the installed Fury. Refresh an existing tab to load the guided interface. New-machine installation is in [QUICKSTART.md](../QUICKSTART.md).

Use the single blue button through all five steps: line signal → joint → evidence → unit scope → decision and token economics. The first step starts the actual local investigation while the scene changes. The evidence step plays the synthetic clip and links its cursor to discrete torque/angle records. Scope and decision wait for a completed result. The last button prepares a fresh walkthrough. Back and the right/left arrow keys work throughout; Space advances when it is not editing a field or activating a focused control.

There is no presenter login, key entry, scenario menu or scene-control panel. The browser automatically receives a capability for its own synthetic session. Optional clicks open an actual fastener record, an exception unit passport, supporting evidence or exports. Preparing a simulated hold still requires an exact draft and an explicitly named approval. These are demo-state changes only.

All five steps fit the tested desktop viewports: 1920×1080, 1440×900, 1366×768 and 1280×720, with no page or core-panel scrolling. Drawers may scroll for complete records. Touch/drag or the pointer can orbit the scene. A functional 2D source view handles unavailable WebGL. The browser renders locally; Fury serves the evidence and inference.

The value screen shows generation input/output tokens from this particular run and its measured wall time. The model chain includes the SQL worker, synthesis and second audit; embeddings/reranking are excluded from the generation-cost arithmetic. Change the illustrative USD token rates or investigation volume to explore metered charges. This is not provider pricing, validated savings or total ownership cost. Incomplete usage remains unknown and disables extrapolation.

A recorded installation says so before starting and keeps a recording badge throughout. Its timings/tokens are historical, not work performed on the receiving computer. It calls no model. A live run that fails retains its failure and offers retry or explicitly labelled recorded recovery; it never silently becomes a successful recording.

“What runs on Fury” explains the local workload and opens measured compute, a read-only following display or lightweight mobile evidence for the current session. Mobile questions are independent when live inference is enabled; they cannot change the stage. Recorded installations disable unavailable live questions. Remote clients receive evidence; no public tunnel is created.

Run `.venv/bin/python scripts/validate_guided_ui.py` for the current browser acceptance. `docs/captures/guided/` holds the audit and value-screen captures. The older general tool-loop interface remains at `/legacy`; its full vision/golden acceptance gate is separate from the working guided telemetry/document slice. Vision is unavailable and footage is synthetic.
